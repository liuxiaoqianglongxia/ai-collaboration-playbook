# 001-heartbeat-readonly

## 目标

验证 Codex 是否可以建立项目级只读心跳机制，用于定期读取事实源、报告状态和发现阻塞，而不是执行写入或自动部署。

## 输入

- 项目仓库 URL。
- 项目级入口文件，例如 `CHATGPT_START_HERE.md`、`CURRENT.md`、`TASKS.md`、`reports/latest.md`。
- 用户明确授权的只读检查范围。

## 只读范围

- 读取 GitHub 文件。
- 读取项目状态文档。
- 汇总未完成任务、阻塞项和最近报告。
- 可选读取 CI 状态或 issue 状态，但不修改。

## 禁止事项

- 不写文件。
- 不改任务状态。
- 不运行部署。
- 不重启服务。
- 不改数据库。
- 不创建生产自动化。
- 不把心跳作为生产守护进程。

## 输出

- 一份只读心跳报告。
- 报告应说明当前项目状态、发现的问题、建议下一步和是否需要人工介入。

## 验收标准

- 报告只基于事实源，不凭聊天历史猜测。
- 没有任何写操作。
- 没有触碰生产环境。
- 能明确指出下一步是否需要任务包。

## 是否可升级为稳定模块

暂不升级。只有在多个项目中证明只读心跳能减少状态误判，且不会诱发自动写入或生产误操作后，才考虑升级。
