# Hermes → Codex 翻译笔记

## 一、核心判断

不要把 Hermes 原样搬进 Codex。

正确方向是把 Hermes 的组织哲学翻译成 Codex 的工程执行系统。

Hermes 是方法论来源，不是 V4 默认执行组件。

## 二、Hermes 可以提供什么

Hermes 体系中值得吸收的不是某个具体运行时，而是组织思想：

- 角色分工
- 技能沉淀
- 记忆压缩
- 任务边界
- 执行报告
- 多线协作
- 长期状态维护

这些思想可以启发 Codex 的任务文件、报告文件、实验室模块和工程增强流程。

## 三、不能直接照搬什么

不应把以下内容原样搬进 Codex：

- Hermes 的运行时结构。
- Hermes 的私有记忆库。
- Hermes 的技能目录。
- Hermes 的角色身份系统。
- Hermes 的本地路径、脚本、密钥或 profile。
- 任何与具体业务项目绑定的内部上下文。

## 四、翻译成 Codex 后应该是什么

在 Codex 体系里，对应关系应是：

- Hermes 的角色分工 → GitHub 任务文件中的职责边界。
- Hermes 的 skill → 可审计、可复用的工程任务模板。
- Hermes 的 memory → GitHub 中的 CURRENT / DECISIONS / reports。
- Hermes 的 agent → Codex 组织本地工具与辅助分析的执行角色。
- Hermes 的运行日志 → GitHub 报告与验收记录。

## 五、稳定边界

V4 默认组件仍是 ChatGPT、GitHub、Codex、Claude Code。

Hermes 的经验可以进入方法论和实验室，但不能未经验证就变成默认执行组件。
