# 生产安全检查清单

> 用途：任何涉及生产环境、部署、数据库、密钥、端口、服务重启、云资源或线上流量的任务，必须额外使用本清单。

## 默认原则

生产环境不是开发环境。未经明确授权，不得执行任何会改变生产状态的操作。

## 生产身份确认

- [ ] 已确认当前环境是否为生产。
- [ ] 已确认服务器、域名、端口、服务名。
- [ ] 已确认用户是否明确授权生产变更。
- [ ] 已确认是否有其他会话或人员正在操作同一环境。

## 备份检查

- [ ] 数据库变更前已有备份。
- [ ] 配置变更前已有备份。
- [ ] 部署变更前已有回滚版本。
- [ ] 备份路径已记录。
- [ ] 回滚命令或回滚步骤已记录。

## 禁止事项

未经明确授权，不得：

- 重启生产服务。
- 停止生产服务。
- 修改生产数据库。
- 修改生产 `.env` 或密钥。
- 修改 nginx / cloudflared / systemd / docker compose。
- 清理生产磁盘。
- 删除备份。
- 迁移端口。
- 执行 force reset、force push 或破坏性清理。

## 变更前检查

- [ ] 已说明变更目标。
- [ ] 已说明影响范围。
- [ ] 已说明预计风险。
- [ ] 已说明回滚方案。
- [ ] 已说明健康检查方式。
- [ ] 用户已明确确认。

## 变更后检查

- [ ] 服务状态正常。
- [ ] 健康检查通过。
- [ ] 关键页面或接口可访问。
- [ ] 日志无明显异常。
- [ ] 回滚方案仍可用。
- [ ] 报告已写回 GitHub。

## 停止条件

只要出现以下任一情况，必须停止：

- 无法确认是否生产环境。
- 无备份。
- 无回滚方案。
- 无用户明确授权。
- 发现并发操作。
- 发现当前任务与生产状态不一致。
- 操作可能影响其他项目或服务。

## 验收标准

生产任务只有在备份、授权、变更、健康检查、报告、回滚路径全部明确后，才可给 PASS。
